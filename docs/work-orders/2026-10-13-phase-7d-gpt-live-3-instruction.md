# Phase 7D-GPT-LIVE-3 — 실제 Garmin 데이터 연결 준비 (사용자 지시, 원문 보존)

RunningAI OAuth Smoke E2E 검증을 완료했다.

ChatGPT에서 직접 MCP 읽기 도구 7종을 모두 호출했으며 7/7 PASS.

확인된 값:

* 최근 합성 활동 6건
* 2026-10-12 분석 디커플링 6.677%
* HRV 60ms / baseline 61.9ms
* CTL 50.18 / ATL 42.60
* 젖산역치 165bpm / 310s/km
* TrainingContextV2 정상
* 훈련 추천 정상 (합성 부상 상태 RESOLVED)

## 목표

기존 ChatGPT OAuth 연결을 유지하면서, 실제 Garmin·Intervals.icu 데이터 사본으로 전환할 준비를 한다.

## STEP 1 — E2E 결과 보존

* 도구 7종 성공 결과 기록
* OAuth 인증 및 Worker→Tunnel→Gateway→Spring 호출 성공 기록
* 민감 토큰·개인정보 로그 노출 여부 확인
* 미커밋 작업물 보존

## STEP 2 — 실제 데이터 사본 준비

* 운영 PostgreSQL은 읽기 전용 백업
* 별도 사본 DB 생성
* 사본에 Flyway V21~V23 적용
* 개발 Spring 별도 포트 사용
* 외부 Garmin/Intervals 동기화 OFF
* 모든 운동 게시·드래프트 쓰기 기능 OFF
* MCP 읽기 7종만 허용

실제 무릎 상태는 마지막 사용자 보고에 근거해 ACTIVE로 취급한다. 보고 시각을 임의로 최신화하거나 RESOLVED로 바꾸지 않는다. 상태가 오래됐거나 불명확하면 훈련 허용 없이 차단한다.

## STEP 3 — 실제 데이터 로컬 검증

2026-10-11 서울레이스 하프를 우선 확인한다.

* 거리 21.24km
* 기록 1:52:04
* 보폭·접지시간·러닝파워
* 심박·케이던스·페이스 변화
* 후반 페이스 저하
* 회복 지표 및 훈련부하
* 젖산역치 출처 및 최신성

DB에 저장된 실제 수치를 기준으로 검증한다. 데이터가 없으면 없다고 보고한다.

## STEP 4 — 외부 전환 전 보안 확인

* 기존 합성 데이터 연결은 유지
* 실제 데이터용 개발 인스턴스는 localhost에서만 기동
* Worker·Gateway 인증 및 사용자 제한 확인
* 무인증·위조 토큰·권한 부족 차단 확인
* 직접 Tunnel 접근 시 인증 우회 불가능 확인
* 실제 데이터가 로그 및 오류 메시지로 유출되지 않는지 확인
* 운영 DB가 외부 MCP 경로에 포함되지 않는지 확인

## STEP 5 — 사용자 승인 대기

실제 데이터 로컬 검증이 끝나면 다음을 보고한다.

1. 사본 DB 및 개발 Spring 준비 상태
2. MCP 실제 데이터 7종 로컬 검증 결과
3. 실제 Garmin 데이터 조회 가능 여부
4. 기존 합성 데이터 연결에서 전환할 정확한 설정
5. 보안 검증 결과
6. 전환 실패 시 즉시 합성 데이터로 복구하는 절차

실제 개인 데이터를 공개 HTTPS 경로에 연결하는 변경은 아직 실행하지 말고 STOP한다.

기존 운영 Spring 18080, 운영 DB, Relay, Watchface, Funnel, Watchdog, Canonical main, origin은 변경하지 않는다.

새 기능 개발이나 웹 UI 개발은 하지 않는다.
