# Phase 8A 지시서 (원문 그대로)

> 아래는 사용자가 준 지시 원문이다. 편집하지 않는다.

RunningAI Phase 8A — Garmin 자동 동기화 및 회복 데이터 보강

역할

RunningAI 시니어 백엔드 아키텍트 / 개발 리드 / QA

Phase 7F 기능 감사가 완료되었다.

이제 추가 비용 없이 기존 시스템을 유지하면서 RunningAI 기능 완성을 시작한다.

목표

1. Garmin 증분 동기화 스케줄러를 안전하게 사용할 수 있도록 완성한다.
2. Garmin 회복 데이터의 누락 구간을 백필할 수 있도록 한다.
3. RunningAI 분석과 TrainingContextV2가 최신 데이터를 반영하게 한다.
4. 기존 AI Coach, OAuth, MCP, 부상 게이트 및 훈련 게시 기능을 보호한다.

작업 1 — Garmin 증분 동기화

현재 스케줄러가 OFF인 이유와 실제 코드를 확인한다.

다음 항목을 검증하고 필요한 부분만 구현한다.

* 마지막 성공 시점 저장 및 재실행
* 신규 활동 증분 조회
* 기존 Activity / ActivityRaw 중복 방지
* 원본 데이터 보존
* 실패 후 재시도 및 부분 실패 복구
* 동시 실행 방지
* 최신 동기화 시각 및 처리 건수 기록
* 인증 만료 및 Garmin 429 대응
* 수집 실패 시 기존 데이터 보존

기존 구현이 정상이면 재구현하지 않는다.

운영 스케줄러를 활성화하지 말고 개발 DB에서 반복 실행·중복 처리 테스트를 먼저 완료한다.

작업 2 — 회복 데이터 백필

Garmin 회복 데이터의 실제 누락 날짜를 조사한다.

확인 지표:

* HRV
* 수면 시간·점수
* 안정시 심박수
* Body Battery
* Stress

원본 Garmin 데이터가 존재하는 날짜만 백필한다.

데이터가 없는 날짜를 0 또는 임의 추정값으로 채우지 않는다.

기존 데이터에 대해 불필요한 덮어쓰기를 하지 않는다.

백필 결과가 개인 기준선 계산과 TrainingContextV2에 올바르게 반영되는지 검증한다.

작업 3 — 데이터 신선도 및 품질

각 데이터 소스별로 다음 정보를 확인한다.

* 마지막 성공 수집 시각
* 최신 데이터 날짜
* 데이터 지연 시간
* 누락 일수
* 분석 완료 여부
* 수집 실패 여부

수집 실패를 데이터 없음과 구별할 수 있도록 한다.

기존 API를 우선 재사용하고, 필요한 경우에만 최소한의 상태 조회 기능을 추가한다.

작업 4 — 테스트

다음 시나리오를 반드시 테스트한다.

1. 신규 러닝 활동 1건 수집
2. 동일 활동 중복 수집
3. Garmin 요청 429 발생
4. Garmin 인증 실패
5. 수집 도중 프로세스 종료
6. 스케줄러 중복 실행
7. 회복 데이터 일부 누락
8. 원본에 없는 회복 날짜
9. TrainingContextV2 갱신
10. 기존 부상 안전 게이트 및 OAuth 회귀

기존 테스트 전체를 재실행하고 신규 테스트를 추가한다.

작업 범위 및 승인

이번 Phase에서 승인된 사항:

* 개발 Worktree 코드 수정
* 개발용 DB 또는 테스트 Fixture 사용
* 필요한 테스트 추가 및 실행
* 마이그레이션 코드 작성과 개발 환경 검증
* 설계 문서 및 결과 보고서 작성

별도 승인 없이는 금지:

* 운영 DB 데이터 변경
* 운영 Garmin 수집 스케줄러 활성화
* 운영 회복 데이터 백필
* Cloudflare Worker 재배포
* 실제 Intervals.icu 게시
* OAuth scope 변경
* runningai:publish 활성화
* Git commit / merge / push
* 유료 인프라 또는 서비스 사용
* 레거시 C:\running-ai 변경

완료 기준

1. 증분 동기화의 중복 방지와 재시도 테스트 PASS
2. 회복 데이터 백필 테스트 PASS
3. TrainingContextV2 정상
4. 기존 1,442개 Spring 테스트 회귀 없음
5. 운영 환경에 적용할 설정 및 예상 영향 명시
6. 운영 적용 전 최종 승인 요청

코드를 구현하고 개발 환경에서 충분히 검증한 뒤 결과를 보고하라.

운영 적용 전 STOP.
