Phase 7E-4 — RunningAI 운영 전환 실행 승인

Phase 7E-3 검증 결과를 승인한다.

A~F 운영 전환 작업을 지금 실행해 줘.

목표는 최대한 빠르게 운영 DB를 V26으로 전환하고, 실제 과거 운동 기록을 통합한 뒤 ChatGPT에서 실데이터를 조회할 수 있도록 만드는 것이다.

별도의 계획 수립 Phase나 추가적인 승인 대기 없이 아래 순서로 진행한다.

1. 운영 전환 전 필수 확인

* main-3의 8개 커밋 및 Clean 상태 확인
* 운영 Spring 18080, Gateway 17910, Relay, Watchface, Funnel, Watchdog 상태 확인
* 운영 PostgreSQL의 전체 백업 생성
* 백업 파일 무결성과 복원 가능성 확인
* 기존 운영 DB의 활동 8건 및 샘플 21,828개 확인
* 현재 설정과 복구 절차 보존

백업이 실패하거나 복원 가능성을 확인할 수 없다면 즉시 STOP한다.

2. RISK-H3 해결

A. 운영 Spring의 DB_URL을 127.0.0.1로 명시한다.

B. 연결 정상 확인 후 Docker Compose의 PostgreSQL 포트 바인딩을 127.0.0.1:5432:5432로 변경한다.

C. 필요한 컨테이너 재생성 후 다음을 검증한다.

* 기존 DB 데이터 보존
* 운영 Spring 접속 성공
* 로컬 DB 연결 정상
* LAN 및 Tailnet에서 5432 접근 차단
* IPv4/IPv6 외부 리스너 미노출
* Relay, Watchface 및 기존 서비스 회귀 없음

보안 차단이 확인되지 않으면 실데이터 MCP 외부 연결을 진행하지 않는다.

3. 운영 DB V21~V26 적용

* 검증된 Flyway 마이그레이션을 순서대로 실행
* 기존 데이터 보존 확인
* Garmin 8건 재분석
* 7건의 러닝 다이내믹스 보강 확인
* 분석 버전 및 입력 Digest 정합성 확인

실패 시 임의로 Flyway History를 수정하지 않는다.

4. 과거 데이터 Import

반드시 다음 순서로 진행한다.

1. Intervals 전용 활동 25건 Import
2. Strava 신규 활동 15건 Import
3. 기존 33건 FIT 보강
4. 랩·파워·원본 출처 확인
5. 중복 및 멱등성 검증

기대 결과:

* 활동 총 48건
* 기존 Garmin 8건 보존
* Intervals 샘플 46,880개
* Strava 신규 샘플 6,498개
* 신규 중복 활동 0건
* 기존 심박·센서 값의 잘못된 덮어쓰기 0건

운영 원본과 리허설 결과를 비교하고 차이가 있다면 원인을 조사한다. 수치를 맞추기 위해 데이터를 임의로 수정하지 않는다.

5. ChatGPT 실제 데이터 읽기 전환

* 합성 환경 18081은 유지
* 실데이터 MCP 서버의 실제 DB 대상 확인
* 7개 Read Tool만 노출
* OAuth 사용자 제한 및 runningai:read 권한 확인
* publish_workout 등 쓰기 도구 차단
* Gateway의 RUNNING_AI_GATEWAY_TARGET_URL을 실데이터 MCP 서버로 전환
* Gateway 재시작 및 인증·조회 확인

실데이터 서버가 쓰기 도구를 노출하거나 인증 범위가 예상과 다르면 전환하지 않는다.

6. 검증

* 운영 Spring 정상
* PostgreSQL 외부 노출 차단
* Flyway V26
* 활동 48건 및 데이터 품질
* 기존 분석 결과 보존
* MCP Read 7종 정상
* ChatGPT OAuth Smoke 조회 준비 완료
* Watchface, Relay, Funnel, Watchdog 정상
* 재실행 시 중복 0건

ChatGPT 앱에서 사용자 OAuth가 필요한 마지막 조회는 사용자가 직접 확인할 수 있도록 안내한다.

7. 실행 정책

이번 지시서로 A~F 운영 전환을 승인한다.

단, 다음 상황에서는 즉시 STOP하고 보고한다.

* 백업 또는 복원 검증 실패
* 운영 DB 데이터 불일치
* 외부 PostgreSQL 노출 지속
* 기존 서비스 복구 불가능
* OAuth 인증 또는 권한 검증 실패
* 예상하지 못한 데이터 손실 위험

운영 DB의 전체 삭제, 볼륨 삭제, 강제 초기화, 임의 데이터 재작성, 인증 우회는 금지한다.

Canonical main 병합과 origin push는 이번 승인에 포함하지 않는다.
