목표

기존 Garmin 증분 동기화 스케줄러를 운영에서 안전하게 활성화하기 위한 최종 사전 검증을 수행한다.

이미 구현된 기능을 재개발하지 않는다.

작업 1 — 스케줄러 확인

실제 코드 및 운영 설정을 확인하라.

1. 스케줄 주기와 활성화 설정
2. 마지막 성공 체크포인트
3. 현재 시각 기준 조회 범위
4. Garmin 예상 요청량
5. 401/429 및 타임아웃 처리
6. 중복 실행 차단
7. 프로세스 재시작 후 동작
8. 실패 이력과 연속 실패 기록
9. 수동 동기화와 스케줄러 동시 실행 방지
10. Watchdog과 충돌 여부

설정의 기본값과 환경변수 오버라이드를 구분해 기록한다.

작업 2 — 실제 운영 수동 동기화 사전 점검

아직 동기화를 실행하지 않는다.

운영 DB 읽기 전용으로 다음 기준선을 수집한다.

* activity / activity_raw
* garmin_sync_state
* garmin_sync_attempt
* 마지막 성공 시각
* 최근 활동 날짜
* 운영 DB 백업 상태

수동 실행 시 예상되는 외부 요청과 DB 변경 범위를 계산한다.

첫 성공 후 확인할 항목:

* 동기화 결과 SUCCESS/PARTIAL/FAILED
* 신규 활동 건수
* 중복 건수
* 원본 보존
* 체크포인트 변화
* 오류 정보 저장
* 기존 러닝 분석 정합성

작업 3 — 운영 활성화 계획

수동 동기화가 성공한 이후에만 스케줄러를 켜도록 계획한다.

* 기존 활성화 스위치 재사용
* 임의의 주기 단축 금지
* 새 스케줄러 추가 금지
* Garmin 429 발생 시 요청 폭주 방지
* Garmin 401 발생 시 인증 상태 확인 및 중지 기준 마련
* 연속 실패 발생 시 비활성화 및 복구 절차 명시
* 활성화 후 최초 실행 로그 관측

운영 회복 백필은 스케줄러 안정화 이후 별도 승인으로 실행한다.

작업 4 — 발견된 결함 및 Git 상태

추가로 아래 사항을 조사만 수행한다.

1. 존재하지 않는 경로의 404와 지원하지 않는 메서드의 405가 500으로 처리되는 문제를 구분하고 재현한다.
2. GlobalExceptionHandler 최소 수정 범위와 회귀 테스트 계획을 작성한다.
3. Spring tools/list 13개와 Gateway 노출 도구 목록을 구분하여 기록한다. publish 도구가 실제 호출 가능한 상태라고 추정하지 않는다.
4. Phase 7F Worker 운영 버전과 Git 미커밋 변경의 차이 및 안전한 정리 방법을 작성한다.
5. 향후 게시 실패 이력용 Flyway V29 예약 사항을 확인한다.

위 항목은 이번 작업에서 수정하지 않는다.
